## 一、环号体系解析：数据源头溯源

### 1.1 环号从哪里来？

环号（RING ID）**并非人工设定，而是直接来源于盾构机施工日志的原始CSV数据**。

在 `TBM_Cutter_Wear_Project/data/processed/steady_260207.csv` 等文件中，"环号"列（原始列名`环号`）是盾构司机每推进一环（约1.5m行程）后在PLC系统中记录的时间戳标记，代表当前掘进环的编号。

原始数据结构如下：
```
日期,环号,总推进力,刀盘转速,推进速度,刀盘扭矩,P2.1泵电流,...
2026-02-07 00:00:04,121,12500,3.2,25,850,...
2026-02-07 00:00:05,121,12480,3.2,25,848,...
...
2026-02-07 02:45:12,122,13020,3.5,28,920,...
```

### 1.2 本项目5日数据环号分布

| 日期 | 文件 | 环号 |
|------|------|------|
| 2026-02-07 | steady_260207.csv | Ring 121, 122 |
| 2026-02-08 | steady_260208.csv | Ring 123 |
| 2026-02-09 | steady_260209.csv | Ring 125 |
| 2026-02-10 | steady_260210.csv | Ring 127 |
| 2026-02-11 | steady_260211.csv | Ring 129 |

**关键发现**：环号从121开始，因为这是武汉两湖隧道工程盾构机实际施工的起始环号。每日的`环号`值由PLC自动记录，施工日志在换刀后清零重新计数，因此本项目5天掘进数据覆盖了Ring 121至Ring 130的连续10个环（其中缺失Ring 124, 126, 128等是因为开仓换刀停机期间无掘进数据）。

### 1.3 环号列如何被代码使用

在 `load_and_engineer_features()` 中（第97-99行）：
```python
df['ring_id'] = df['环号']  # 直接从原始CSV读取，无任何人工干预
```

在 `aggregate_to_ring_level()` 中（第325-338行），帧级MSE按`ring_id`分组后求均值：
```python

hi_values = [hi[r]/cnt[r] for r in rings_to_use]  # 环号→均值
```

## 二、网络架构全解构：TS-VAE 自监督学习拓扑

### 2.1 整体架构拓扑图（文字描述）

```
┌─────────────────────────────────────────────────────────────┐
│                    INPUT: 原始传感器数据流                    │
│  总推进力F_v | 刀盘扭矩T | 推进速度v | 刀盘转速RPM |         │
│  P2.1泵电流I_p21 | 主油箱油温T_oil | 切削比能SE | ...      │
│                    (10维核心物理场通道)                     │
└─────────────────────────────────────────────────────────────┘
                              │
                    Z-Score标准化
                              ▼
┌─────────────────────────────────────────────────────────────┐
│            SLIDING WINDOW: 时序窗口切片算子                   │
│  窗口长度: T=60秒  |  滑动步长: S=30秒                        │
│  输出: X ∈ ℝ^(B × 60 × 10)  三维时序张量                   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    TS-VAE ENCODER (编码器)                   │
│                                                              │
│  输入层: X (B, 60, 10)                                       │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────┐               │
│  │  Layer 1: nn.GRU(10→64)                 │               │
│  │  Layer 2: nn.GRU(64→64)                │               │
│  │  输出最后隐状态 h_T: (B, 64)             │               │
│  └─────────────────────────────────────────┘               │
│     │                                                        │
│     ▼  h_T                                                    │
│  ┌─────────────────────────────────────────┐               │
│  │  μ = W_μ · h_T + b_μ    (64→16)        │               │
│  │  logσ² = W_σ · h_T + b_σ  (64→16)      │               │
│  └─────────────────────────────────────────┘               │
│     │                                                        │
│  Reparameterization Trick:                                  │
│     z = μ + σ ⊙ ε,   ε ~ 𝒩(0, I)                           │
│     │                                                        │
│     ▼ z ∈ ℝ^(B × 16)                                        │
│  潜在空间: Z ∈ ℝ^(B × 16)  (低维流形)                       │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    TS-VAE DECODER (解码器)                   │
│                                                              │
│  输入: z ∈ ℝ^(B × 16)                                        │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────┐               │
│  │  h_0 = tanh(W_init · z + b_init)       │               │
│  │  (16→128: 2层×64维隐状态)               │               │
│  └─────────────────────────────────────────┘               │
│     │ h_0                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────┐               │
│  │  Layer 1: nn.GRU(16→64)                │               │
│  │  Layer 2: nn.GRU(64→64)                │               │
│  │  自回归展开 T=60 步                     │               │
│  └─────────────────────────────────────────┘               │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────┐               │
│  │  X̂ = W_out · h_T + b_out               │               │
│  │  (64→10)                                │               │
│  └─────────────────────────────────────────┘               │
│     │                                                        │
│     ▼ X̂ ∈ ℝ^(B × 60 × 10)                                     │
│  重构输出: 重构时序张量                                      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
              ┌──────────────────────────────┐
              │     ELBO LOSS:               │
              │  L = L_recon + β · L_KL     │
              │  L_recon = MSE(X, X̂)         │
              │  L_KL = D_KL(q(z|X)‖N(0,I)) │
              └──────────────────────────────┘
```

### 2.2 编码器（EncoderGRU）详细层结构

| 层类型 | 输入维度 | 输出维度 | 说明 |
|--------|---------|---------|------|
| GRU Layer 1 | (B, 60, 10) → (B, 60, 64) | hidden state (B, 60, 64) | 第一层双向或单向GRU |
| GRU Layer 2 | (B, 60, 64) | hidden state (B, 60, 64) | 第二层GRU |
| 取最后时刻隐状态 | — | h_T: (B, 64) | 取T=60时刻的隐向量 |
| FC μ | (B, 64) | (B, 16) | 潜在均值推断 |
| FC logσ² | (B, 64) | (B, 16) | 潜在对数方差推断 |

**输出**：`mu ∈ ℝ^(B×16)`，`logvar ∈ ℝ^(B×16)`

### 2.3 解码器（DecoderGRU）详细层结构

| 层类型 | 输入维度 | 输出维度 | 说明 |
|--------|---------|---------|------|
| FC_init | (B, 16) | (B, 128) = 2×64 | 潜在向量→初始隐状态 |
| tanh激活 | — | h_0 ∈ ℝ^(2×B×64) | 初始隐状态 |
| GRU Layer 1 | (B, 60, 16) | (B, 60, 64) | 自回归，z广播至所有时刻 |
| GRU Layer 2 | (B, 60, 64) | (B, 60, 64) | 第二层GRU |
| FC_out | (B, 60, 64) | (B, 60, 10) | 重构输出 |

### 2.4 参数量统计

| 模块 | 参数量 |
|------|--------|
| Encoder GRU (2层) | 2 × (10×64 + 64×64 + 2×64) ≈ 22,528 |

### 2.5 健康基线（Healthy Baseline）定义

**健康基线 = 前两日掘进数据（2026-02-07 + 2026-02-08），对应环号 Ring 121 + 122 + 123**。

物理意义：这两个自然日内，盾构刀具处于全新状态，尚未经历显著磨损，其多物理场耦合传导特征（推力-电流-温度协同关系）是系统的"健康流形基准"。

在代码中（第545-547行）：
```python
df_healthy = df_scaled[
    pd.to_datetime(df_scaled['date']).dt.date <= pd.to_datetime('2026-02-08').date()
]
```

这一选择符合无监督学习的"纯净基线"原则：仅用正常工况数据训练，让网络学习"正常系统应该如何协同工作"，而不是学习"异常如何表现"。

### 2.7 网络输出与HI的数学关系

```
对于任意测试帧 i（来自任意环）：

1. 输入: x_i ∈ ℝ^(60×10)  ——真实多物理场时序窗口
2. 编码: z_i = ENCODER(x_i) ∈ ℝ^16  ——潜在表征
3. 重构: x̂_i = DECODER(z_i) ∈ ℝ^(60×10)  ——网络生成的"期望正常态"
4. 帧级误差: MSE_i = (1/T·C) · ∑||x_i - x̂_i||²

     MSE_i 的物理含义：
     ├── 输入信号符合健康流形 → 解码器完美还原 → MSE ≈ 0
     └── 刀具磨损导致物理信号异变 → 解码器无法还原 → MSE ↑↑

5. 环级聚合: HI(R) = mean(MSE_i) for all i where ring_id=R
```

## 九、模块三 CLAUDE.md 技术规范（更新版）

```
### 模块三：无监督表征学习与退化指标构建

架构：Multivariate TS-VAE（双层GRU编码器 + 对称双层GRU解码器 + 重参数化采样）
参数量：85,162
潜在维度：d=16
输入：X∈ℝ^(B×60×10)  三维时序张量（B=batch, 60=时序步长, 10=核心物理通道）
输出：重构张量X̂∈ℝ^(B×60×10) + 潜在向量z∈ℝ^(B×16)

健康基线定义：仅使用前两日（2026-02-07至2026-02-08，Ring 121-123）数据训练
损失函数：ELBO = MSE(X, X̂) + β·D_KL(q(z|X)∥N(0,I))，β=0.001
训练保护：num_workers=0（Windows防死锁），Early Stopping Patience=8

HI(R)计算：帧级MSE → 按环号分组 → 环内均值 → HI(R)序列
MSE_frame = (1/T·C)·Σ||x_t,c - x̂_t,c||²，物理单位为标准化量纲
HI(R) = mean(MSE_frame) for all frame i where ring_id=R

物理意义：
- 网络固化"正常多物理场耦合传导流形"
- 刀具磨损→物理信号偏离健康流形→解码器无法还原→MSE放大
- MSE放大本质：额外机械耗散做功导致输入信号超出解码器学习到的正常协同规律

可视化输出：
- Fig 8: SE/I/F_v三通道实测vs重构波形 + 残差填充
- Fig 9: UMAP 2D潜在流形轨迹（环号渐变色彩编码）
- Fig 10: HI(R)全生命周期退化曲线 + 5点滑动平均
- Fig 11: 机械/电气/热力/能效四大物理场MSE贡献热力图
```
